# 04. Recommend and Pitch the Vertical Recommendation

> Course: **OpenAI Consultative Solutions Practitioner – Foundations**  
> Sub-course: **Vertical Solution Application**  
> Section: **Recommend and pitch the vertical recommendation**

---

## 1. Mục tiêu

Section cuối cùng biến analysis thành một recommendation mà customer có thể hiểu và hành động.

Một strong vertical recommendation phải trả lời:

```text
Why this workflow?
Why this route?
Why does it matter?
Why is it trustworthy enough?
Why is the customer ready enough?
What must be validated next?
```

Pitch không phải product demo script.

Pitch là **compressed reasoning**.

---

# 2. Recommendation structure

Một cấu trúc mạnh:

```text
1. Vertical/business context
2. Priority
3. Workflow pain
4. Recommended solution pattern
5. Surface/route
6. Expected value
7. Trust requirements
8. Readiness assumptions
9. Evidence / uncertainty
10. Next step
```

---

# 3. The vertical recommendation formula

```text
Because [business/vertical priority],
the current [workflow] creates [specific pain].

We recommend [solution pattern / route]
to change [specific workflow step].

This could improve [operational metric]
and contribute to [business outcome].

Because this workflow requires [trust requirement],
the design should include [control/review/source boundary].

The key readiness assumptions are [X, Y, Z].

The next step is [validation/handoff]
to prove [specific uncertainty].
```

---

# 4. Pitch starts with customer context, not AI capability

Weak:

```text
"Our models can summarize, reason and use tools."
```

Stronger:

```text
"Your analysts spend significant time assembling information
before they can apply judgment. A more credible first route is..."
```

Customer hears:

```text
their workflow
their pain
their outcome
```

before product detail.

---

# 5. Use vertical language carefully

A good pitch uses customer terminology:

```text
workflow names
business metrics
data sources
review steps
risk terminology
```

But do not fake expertise.

If a domain term is unclear, use precise workflow language rather than jargon.

---

# 6. Recommendation must show “why this route”

Do not say only:

```text
"Use ChatGPT Work."
```

Say:

```text
"The task is a delegated, multi-step knowledge workflow:
gather sources, analyze, and produce a review-ready artifact.
That interaction pattern is why a delegated work surface fits."
```

Route reasoning creates credibility.

---

# 7. Value narrative

Value should be a chain:

```text
Workflow change
→ metric
→ business outcome
```

Example finance:

```text
Less manual source gathering
→ shorter memo preparation time
→ more analyst capacity
```

Avoid:

```text
"AI improves productivity."
```

---

# 8. Trust narrative

Do not hide trust requirements.

A strong recommendation says:

```text
"Because the workflow relies on approved financial information,
the solution should preserve source traceability and analyst review."
```

Trust is part of the pitch, not an appendix.

---

# 9. Readiness narrative

A credible pitch names what is not yet proven.

Example:

```text
"The business owner and workflow are clear.
The remaining questions are source access and review quality,
so the next step should be a representative validation session."
```

This is stronger than pretending full certainty.

---

# 11. Example pitch — Financial Services

### Context

Analysts spend hours collecting and synthesizing approved source material before producing weekly research packs.

### Recommendation

```text
Use a delegated knowledge-work pattern to gather approved sources,
analyze the requested topics and prepare a review-ready pack.
```

### Value

```text
less preparation effort
shorter cycle time
more analyst capacity for judgment
```

### Trust

```text
approved data
source traceability
analyst review
```

### Readiness

```text
workflow and owner clear
need to validate source access + output quality
```

### Next step

```text
representative workflow validation
```

---

# 12. 30-second finance pitch

> The current research workflow spends significant analyst time on source gathering and first-draft synthesis before judgment begins. A credible route is to delegate those repeatable preparation steps while keeping approved sources and analyst review in the loop. If representative tests confirm source access and output quality, the workflow could shorten preparation time and increase analyst capacity. The next step is to validate a small set of real research tasks against the team’s quality bar.

Notice:

```text
workflow
route
value
trust
next step
```

all fit in a short pitch.

# 13. Example pitch — Retail


### Value

```text

```

```text

```

# 14. Example pitch — Healthcare administrative workflow

### Context

Administrative staff repeatedly rewrite standard documents from approved patient/organizational context.

### Recommendation

```text
AI-assisted drafting with authorized data and human review.
```

### Value

```text
less administrative burden
faster document preparation
```

### Trust

```text
privacy
authorized context
review
approved sources
```

### Next step

```text
validate representative documents and governance path
```

Do not broaden this into clinical decision support unless the workflow actually requires it.

---

# 15. Pitch = recommendation + boundary

A credible vertical pitch should communicate not only what AI does but where it **stops**.

Example:

```text
AI prepares draft
→ professional reviews
→ professional makes final decision
```

This makes trust model explicit.

---

# 16. Confidence language

Use language proportional to evidence.

## Strong evidence

```text
"We observed..."
"The current baseline is..."
```

## Hypothesis

```text
"This could..."
"We expect..."
"The route appears credible if..."
```

## Unknown

```text
"This still needs validation..."
```

Avoid false certainty:

```text
"This will reduce cost by 40%."
```

unless customer-specific evidence supports it.

---

# 17. Recommendation quality checklist

Before pitching:

```text
[ ] Is the workflow specific?
[ ] Is user clear?
[ ] Is business outcome clear?
[ ] Is route justified?
[ ] Is value linked to workflow?
[ ] Are trust controls explicit?
[ ] Are readiness assumptions named?
[ ] Is uncertainty honest?
[ ] Is next step specific?
[ ] Is pitch tailored to stakeholder?
```

---

# 18. Anti-patterns

## ❌ Generic industry pitch

```text
"AI will transform healthcare."
```

Too broad.

## ❌ Product-first pitch

```text
"You should use X."
```

without workflow evidence.

## ❌ Fear-based trust pitch

Do not overdramatize regulation/risk.

Be concrete:

```text
what data
what review
what approval
what source
```

## ❌ Hide uncertainty

Credibility increases when uncertainty is named clearly.

## ❌ No next step

Recommendation without progression is incomplete.

# 21. Frontend Developer analogy

When presenting a frontend architecture proposal, a strong explanation is:

```text
User problem
→ interaction design
→ technical pattern
→ tradeoffs
→ expected outcome
→ validation
```

Not:

```text
"Let's use framework X because it's cool."
```

Vertical solution pitching is the same discipline at business-solution level.

# 24. Cheat Sheet

The pitch sentence:

> **For this workflow, in this vertical context, we recommend this route because it changes this step, creates this measurable outcome, respects these trust requirements, and the next credible step is to validate these remaining assumptions.**

# 25. Vocabulary

|---|---|

| Customer-specific | Dựa vào context khách hàng cụ thể |
