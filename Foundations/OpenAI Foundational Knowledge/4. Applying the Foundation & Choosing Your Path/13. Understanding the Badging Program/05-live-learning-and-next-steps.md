# 05 — Live Learning and Next Steps

> **Course:** Understanding the Badging Program  
> **Section:** Live learning and next steps
>
> **Source boundary:** PartnerU-specific live-session attendance requirements are not publicly documented in sufficient detail. Treat any required live session, attendance threshold or badge condition shown inside PartnerU as authoritative. This guide explains how to use live learning and what to do after pathway completion.

---

# 1. Section objective

Sau section này, bạn cần:

- hiểu live learning bổ sung self-paced learning ra sao;
- biết cách chuẩn bị để lấy value từ live session;
- biết next steps sau foundation/badge;
- connect learning to applied customer work;
- xây continuous-learning loop.

---

# 2. Big picture

Self-paced learning:

```text
Concept
→ personal pace
```

Live learning:

```text
Concept
+ discussion
+ scenarios
+ Q&A
+ expert feedback
```

Applied work:

```text
Real problem
→ use knowledge
→ evidence
```

Together:

```text
Learn
→ discuss
→ apply
→ improve
```

---

# 3. Why live learning matters

AI concepts often look simple in text but become difficult in scenarios.

Example:

> “Use RAG for private knowledge.”

Real customer questions:

- Which documents?
- Who can access?
- How fresh?
- What if sources conflict?
- What if retrieval fails?

Live learning lets you explore ambiguity.

---

# 4. Live learning is not just webinar attendance

Passive:

```text
watch
→ leave
```

Active:

```text
prepare
→ participate
→ ask
→ apply
→ capture lessons
```

The second creates capability.

---

# 5. Prepare before session

Do:

- complete prerequisite content;
- note unclear concepts;
- bring one real scenario;
- prepare 2–3 questions;
- review terminology.

This helps you use expert time well.

---

# 6. Bring a real workflow

Best question:

> “In this support workflow, when would you recommend RAG vs tool access?”

Better than:

> “Can you explain RAG again?”

Real workflows produce transferable learning.

---

# 7. Ask boundary questions

Useful live questions:

- When should we not use this?
- What evidence is needed?
- What are common failure modes?
- What customer readiness matters?
- What must be human-reviewed?

Boundary knowledge improves judgment.

---

# 8. Capture deltas

Do not rewrite everything from live session.

Capture:

```text
What changed my understanding?
What new example clarified the concept?
What rule/exception should be added to notes?
What current product fact changed?
```

This keeps notes useful.

---

# 9. After live session

Within 24 hours:

```text
Review
↓
update notes
↓
apply one concept
↓
write one question
```

Fast consolidation improves retention.

---

# 10. Apply to a customer scenario

Agents.


Now concept becomes reusable.

# 11. Next step after Foundation

Foundation should lead to:

```text
Role-specific pathway
or
product-specific pathway
or
applied project
```

Choose based on current work.

Not:

> collect another badge automatically.

---

# 12. Build a personal learning backlog

Categories:

### Must know now
Needed for current project.

### Next
Needed for upcoming work.

### Later
Interesting specialization.

This prevents curriculum overload.

---

# 13. Create an applied portfolio

For each pathway, save one artifact.

Examples:

### Consultative
- discovery/use-case assessment.

### Technical
- architecture diagram;
- prototype;
- eval plan.

### ChatGPT
- repeatable workflow.

### Codex
- scoped task + review evidence.

### API
- small embedded application.

Artifacts prove more than completion alone.

---

# 14. Build a “decision journal”

When you choose a solution, record:

```text
Customer problem
Chosen pattern
Alternatives considered
Why chosen
Assumptions
What evidence validated it
```

This develops professional judgment.

---

# 15. Continuous product updates

Because OpenAI evolves:

Set habit:

- check official docs;
- review release notes;
- revisit course updates;
- verify model/product claims before customer meetings.

Badging does not freeze knowledge in time.

---

# 16. Community learning

Partner communities can help surface:

- real use cases;
- implementation challenges;
- patterns;
- customer objections;
- lessons learned.

But distinguish:

```text
peer experience
from
official product fact
```

Both are useful for different reasons.

---

# 17. Teach others

Teaching improves retention.

After a course:

> explain 3 core concepts to teammate.

If you cannot explain simply:

> revisit them.

---

# 18. Build reusable cheat sheets

Examples:

```text
RAG vs tool vs fine-tuning
ChatGPT vs API
Agent vs workflow automation
Model selection checklist
Discovery questions
```

These improve real customer conversations.

---

# 19. Practice scenario matrix

Create scenarios by dimension:

```text
Internal vs external users
Read vs write
Static vs live data
Low vs high risk
Single vs multi-step
Low vs high scale
```

Try mapping each to solution.

This improves assessment and delivery.

# 29. 30-60-90 day learning plan

## 30 days
- finish current pathway;
- pass required assessment;
- build one artifact.

## 60 days
- apply in project;
- get feedback;
- start next pathway.

## 90 days
- contribute to customer/internal solution;
- measure result;
- identify specialization.

Adjust to workload.

---

# 30. Common mistakes

1. Live session = passive webinar.
2. Badge = endpoint.
3. Immediately collect next badge.
4. No applied artifact.
5. No product update habit.
6. Peer claim treated as official fact.
7. Assume recording counts as live attendance.
8. No connection between learning and current work.
